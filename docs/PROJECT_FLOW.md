# 项目流程与研究内容

[返回首页](../README.md) · [文档索引](README.md) · [研究问题](RESEARCH.md) · [执行计划](PLAN.md) · [进度看板](PROGRESS.md)

## 1. 我们要研究什么

**一句话**：

> 在同一个长程任务、相同的观测和动作接口下，**显式分层架构（S2 规划 → S1 策略 → S0 控制）相比端到端单层策略，在训练和行动上带来什么可量化的差异？代价是什么？**

**四个子问题**：

| 编号 | 问题 | 指标 |
| --- | --- | --- |
| RQ1 | 分层让训练更省吗？ | 达到 80% 成功率所需环境步数 |
| RQ2 | 分层最终更强吗？ | 四阶段全部完成的 episode 比例 |
| RQ3 | 分层泛化更好吗？ | 未见阶段顺序 / 目标距离 / 扰动下的成功率衰减 |
| RQ4 | 分层的失败可归因吗？ | 失败中「S1 决策错」与「S0 执行失败」的占比；单层无法区分 |

另有一个**代价指标**：接口损失——分层整体性能受 S0 跟踪误差上限约束，这个天花板可以量化。

## 2. 为什么值得研究

1. 分层是主流工程实践（MoRA、VLA 分层、skill-based RL），但公开的**受控对比**很少：多数工作只报自己架构的成功率，不报同任务单层基线。
2. 本仓库有方向性证据但不够受控：Phase-1 的单层 PPO（v1–v5）全部 ≤0.7 m、站桩或乱动，分层达到弯道 20/20、多段 20/20、岔路 40/40——当时是开发过程中的迭代，不是对照实验。
3. 需要一个能讲清楚的量化答案：「分层让达到 80% 成功率所需样本减少 X%，代价是 Y」。

## 4. 每个阶段：输入、动作、产出、判据

### Stage 0 基础设施 ✅

| 项 | 内容 |
| --- | --- |
| 输入 | 空仓库 + Isaac Lab 2.7 + RTX 5060 Ti |
| 动作 | 打通训练链路；预注册协议（冻结种子 E={0..19}、指标、阈值）；每 run 证据束；监控面板与视频；自动同步 |
| 产出 | `locomotion/` 包、`docs/EXPERIMENT_DESIGN.md` v1.0、`run_config.json` + SHA-256、`/api/status` 面板 |
| 判据 | 协议自检 6/6 通过；2 迭代冒烟训练成功；CI 绿 |

### Stage 1 S0 基线 ✅

| 项 | 内容 |
| --- | --- |
| 输入 | Stage 0 的训练栈 |
| 动作 | 平地速度跟踪，PPO/RSL-RL，2048 并行，3 个独立种子，每个 1500 迭代 |
| 产出 | 三份证据束（各 31 checkpoints / 37 文件哈希）；评估报告 |
| 结果 | `vx_rmse 0.0569 ± 0.0011`、`ωz_rmse 0.0872 ± 0.0017`、`fall_rate 0`（阈值 0.15 / 0.2）|
| 用途 | 分层 B 的 S0；单层 A 的子技能基线；接口损失上限估计 |

### Stage 2 任务定义 ✅ 第一版

| 项 | 内容 |
| --- | --- |
| 输入 | Stage 1 的 S0 策略 |
| 动作 | 定义四阶段命令序列：前进 2 m → 左转 90° → 前进 2 m → 停止 1 s；设计 53 维观测（48 基础 − 3 速度命令 + 2 阶段命令 + 4 阶段 one-hot + 2 目标偏差）；阶段性奖励与终止 |
| 产出 | `locomotion/sequence/`，任务 ID `Go2Loco-Sequence-v0` |
| 判据 | 环境可创建、reset/step 正常、阶段状态稳定、观测维度正确（冒烟通过） |

## 7. 风险与止损

| 风险 | 止损 |
| --- | --- |
| 单层 A 训不出来 | 这是**有效结论**（与 Phase-1 一致），但需同时报告训练预算与任务难度，避免「任务设计偏向分层」的质疑 |
| 分层 B 的 S1 训练不稳定 | 降级为规则 S1（脚本生成速度指令），对比变为「规则分层 vs 学习单层」 |
| 时间不够做泛化 | 只保留成功率与样本效率，泛化列为未来工作 |
| 行为录像崩溃 | 不影响主结论；已记录三步排查计划 |

## 8. 一句话记住这个项目

> 不是"训了一个会走路的机器狗"，而是**用受控实验回答分层架构到底值不值**，并把过程、失败和证据都留成可复核的记录。
