# 研究问题：多层架构对机器人训练与行动的价值

[返回首页](../README.md) · [文档索引](README.md) · [架构 v0.2](ARCHITECTURE_V2.md) · [执行计划](PLAN.md)

> **状态**：研究主线（2026-10-23 确立）。取代此前以"仲裁层"为唯一主线的定位；仲裁层保留为层间约束子研究（§8）。

## 1. 研究对象

MoRA 式分层架构与端到端单层架构的**受控对比**。

```text
分层（B）：S2 规划（规则/阶段管理） → S1 策略（高层指令） → S0 控制（locomotion）
单层（A）：观测 + 任务状态 ──────────────────────────────→ 关节动作
```

两者使用**相同的观测接口、相同的任务、相同的评估种子**，唯一差别是有没有显式分层。

## 2. 核心问题

> **在同一个长程任务上，显式分层相比端到端单层，在样本效率、最终成功率、泛化、失败可归因性和模块复用上带来什么可量化的差异？代价是什么？**

## 3. 为什么值得研究

1. **分层是主流工程实践**（MoRA、VLA 分层、skill-based RL、分层 MPC），但公开的**受控实证对比**很少：多数工作只报告自己架构的成功率，不报告同任务单层的基线。
2. **本仓库有现成的对照证据但不够受控**：Phase-1 的单层 PPO（v1–v5）全部 ≤0.7 m、站桩或乱动，分层达到弯道 20/20、多段 20/20、岔路 40/40——方向明确，但当时不是按对照实验设计的（奖励、观测、动作接口都改过）。
3. **面试与写作都需要一个量化答案**：与其说"我用了分层"，不如说"分层让达到 80% 成功率所需样本减少 X%，代价是 Y"。

## 4. 任务设计：命令序列（Command Sequence）

四阶段长程任务，在平地执行：

| 阶段 | 目标 | 成功判据 |
| --- | --- | --- |
| 1 | 前进到 x ≈ 2 m | 位置误差 < 0.3 m |
| 2 | 原地左转 90° | 航向误差 < 10° |
| 3 | 前进到 y ≈ 2 m | 位置误差 < 0.3 m |
| 4 | 停止并保持 1 s | 速度 < 0.1 m/s 持续 1 s |

整个序列成功 = 四个阶段全部完成且未摔倒。

**为什么选这个任务**

- 有明确的长程结构，单层必须隐式学会"当前处于哪一阶段、下一步该做什么"；分层可以显式管理阶段。
- 复用现有 Go2 速度跟踪策略作为 S0，不需要重建底层控制。
- 不需要障碍物或复杂地形，环境工程量可控。
- 阶段成功判据可独立检查，因此失败可以归因到具体阶段。

## 5. 对比组

| 组 | 结构 | 输入 | 输出 |
| --- | --- | --- | --- |
| **A 单层** | 单个策略 | 48 维本体观测 + 阶段编码（one-hot/进度）+ 目标 | 12 维关节目标 |
| **B 分层** | S2 规则 + S1 策略 + S0 策略 | S1：48 维观测 + 当前阶段目标；S0：速度指令 | S1 → 速度指令；S0 → 关节 |
| **C 分层+约束**（子研究） | B + 可验证仲裁层 | 同 B，动作经物理约束检查 | 同 B |

**公平性约定**：A 与 B 获得**相同的任务信息**（阶段/目标都可见）。对比的是"显式分解"与"隐式学习切换"，不是"给不给信息"。

## 6. 指标

| 指标 | 定义 | 用途 |
| --- | --- | --- |
| 成功率 | 完成全部四阶段的 episode 比例 | 最终性能 |
| 样本效率 | 达到 80% 成功率所需的环境步数 | 训练成本 |
| 跟踪误差 | 每阶段的 vx/ωz RMSE | 执行质量 |
| 泛化 | 未见过的阶段顺序/目标距离/扰动下的成功率 | 迁移能力 |
| 失败归因 | 失败 episode 中，S1 决策错误 vs S0 执行失败的占比 | 分层独有的诊断价值 |
| 接口损失 | 用 S0 的跟踪误差与整体成功率的关系估计上限 | 分层的代价 |

## 7. 假设（可证伪）

- **H1**：在长程任务上，分层达到 80% 成功率所需样本显著少于单层（Phase-1 的定性证据支持）。
- **H2**：任务越长、阶段越多，分层的优势越大；在纯速度跟踪这类短任务上两者无显著差异（说明分层不是银弹）。
- **H3**：分层的失败可归因（能区分"高层决策错"与"底层执行失败"），单层不可归因。
- **H4**：分层存在接口损失——整体性能受 S0 跟踪误差上限约束，这个损失可量化。

## 8. 仲裁层的位置（子研究）

原来的"可验证仲裁层"从主线降为**层间约束子研究**：

- 在 B（分层）上增加 C：动作经 C++ 物理检查（支撑多边形/摩擦锥/力矩可行性）后再下发。
- 研究问题：可验证约束能降低多少危险状态、代价多少成功率（原 RQ1–RQ4 保留）。
- 它回答的是"分层内部如何保证可靠性"，而不是"分层有没有价值"。

## 9. 时间预算（3 周）

| 周 | 内容 | 交付 |
| --- | --- | --- |
| W1 | 命令序列环境；单层基线训练；S0 策略验收（当前训练即 S0） | 环境可跑；A 组首个结果 |
| W2 | 分层 S1 训练；A/B 对比（成功率 + 样本效率） | 对比表 |
| W3 | 泛化与失败归因；报告与演示 | 归因表 + 报告 + 视频 |

单项预算超支时按 **泛化 → 失败归因 → 仲裁子研究** 的顺序砍；成功率与样本效率的对比必须保留。

## 10. 风险与降级

| 风险 | 降级方案 |
| --- | --- |
| 单层在命令序列上训不出来 | 结论仍成立（分层能、单层不能），但需同时报告任务难度与训练预算，避免"任务设计偏向分层"的质疑 |
| 分层 S1 训练不稳定 | 降级为规则 S1（脚本生成速度指令），对比变为"规则分层 vs 学习单层"，仍能回答接口价值 |
| 泛化实验时间不足 | 只做成功率与样本效率，泛化列为未来工作 |
| S0 策略未达标 | 用官方预训练 locomotion 策略替代，并在报告中声明 |

## 11. 与当前训练的关系

正在跑的三种子 Go2 速度跟踪训练（S1 平地）有三个用途：

1. **分层组 B 的 S0**：S1 输出的速度指令直接喂给它。
2. **单层组 A 的子技能基线**：用于判断任务难度是否合理。
3. **接口损失的上限估计**：S0 的 `vx_rmse`/`ωz_rmse` 决定整体性能的天花板。

因此这次训练不会浪费，无论最终走 A/B 对比还是仲裁子研究。
