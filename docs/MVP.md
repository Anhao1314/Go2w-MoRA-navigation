# MVP 定义（2026 Q4）

[返回首页](../README.md) · [文档索引](README.md) · [路线图](ROADMAP.md) · [实验协议](EXPERIMENT_DESIGN.md)

## 一句话

> **用 3 周时间交付「一个在 Isaac Lab 训练达标的 Go2 速度跟踪策略，以及它在 MuJoCo 中的迁移损失量化与归因」——证明能定位并解释 sim2real gap 的主要来源，而不是只会在一个仿真器里跑 demo。**

---

## 1. 要解决什么问题

### 1.1 核心问题

**在 Isaac Lab 中训练出的 Go2 速度跟踪策略，不改动任何权重迁移到 MuJoCo 后，性能损失多大？损失的主因是执行器建模、接触参数还是控制延迟？针对主因做参数对齐后，能恢复多少？**

这个问题有三层价值：

- **可量化**：输出是成功率、跟踪误差和失败模式分布，不是"能走"。
- **可归因**：单因素扫描把总损失拆到具体物理参数上，而不是笼统说"仿真有差距"。
- **可迁移**：同样的方法换成真机就是系统辨识流程，面试时可以说明"这套归因方法在真机上如何落地"。

### 1.2 前置问题（测量的前提，不是目标本身）

**能否在冻结协议下复现一个达标的 Go2 速度跟踪策略（3 个独立种子）？**

这是测量的尺子。没有达标策略，"迁移损失"无从定义。因此 P0 训练是必需前置，但项目要解决的问题不是"训练一个策略"。

### 1.3 为什么不是"训练一个 Go2 走路"

| 只做训练 | 本 MVP |
| --- | --- |
| 结果是一个成功率数字 | 结果是一个损失模型 + 主因排序 |
| 换仿真器就失效，无法解释 | 明确知道失效原因与补偿手段 |
| 面试只能讲"我用 PPO 训了 Go2" | 面试可以讲"我量化了 sim2real gap 的构成" |
| 无法回答"仿真真机差距怎么办" | 有完整的归因方法论与数据 |

### 1.4 明确不解决

真机部署、视觉/感知、VLA、算法创新、通用运动智能。

## 2. 用什么方法

### 2.1 阶段 A：基线策略（约 3 天）

| 项 | 设定 |
| --- | --- |
| 任务 | `Go2Loco-S1-Flat-Blind-v0`（平地速度跟踪，vx/ωz ∈ [-1,1]，vy=0） |
| 算法 | PPO（RSL-RL 3.1.2），2048 并行环境，盲观测 48 维 |
| 种子 | 3 个独立训练种子（T1/T2/T3），~43 min/seed（已实测） |
| 评估 | 冻结种子集 E={0..19}，`vx_rmse`、`ωz_rmse`、`fall_rate` |
| 达标线 | vx_rmse ≤ 0.15 m/s，ωz_rmse ≤ 0.2 rad/s；三种子 mean±std，禁止挑最优 |
| 产物 | 每 run 的 `run_config.json` + `sha256_manifest.json`（已实现自动生成） |

### 2.2 阶段 B：迁移环境（约 4 天）

| 对齐项 | 做法 | 风险 |
| --- | --- | --- |
| 模型 | MuJoCo Go2（menagerie / unitree_mujoco） | 与 Isaac 官方资产质量分布可能不同 |
| 观测 | 重建 48 维：base_lin_vel、base_ang_vel、projected_gravity、commands、joint_pos、joint_vel、actions | 关节顺序与符号映射必须逐关节核对 |
| 动作 | 12 维目标位置 → MuJoCo position actuator | Isaac 的 actuator 模型（stiffness/damping/armature）需换算 |
| 时序 | 控制频率对齐 50 Hz（decimation 4 × 0.005 s） | 物理子步不同会改变接触行为 |
| 评估 | 同一命令序列、同一评估种子 E={0..19} | 命令生成器必须两侧共用 |
| 导出 | 策略导出为 TorchScript（备选 ONNX），**零权重改动** | 归一化统计必须随策略一起导出 |

**先做单关节/站立测试**：在跑完整 episode 前，确认 12 个关节的方向、零位、力矩方向一致。这一步能省掉后面 80% 的调试时间。

### 2.3 阶段 C：归因实验（约 5 天）

**单因素扫描**（每次只改一个因素，其余固定为 Isaac 侧标称值）：

| 因素 | 标称 | 扫描范围（初版） | 考察 |
| --- | --- | --- | --- |
| 执行器刚度 kp | Isaac 换算值 | 0.5× / 1× / 2× | 关节跟踪滞后、振荡 |
| 执行器阻尼 kv | Isaac 换算值 | 0.5× / 1× / 2× | 过冲、发热式饱和 |
| 地面摩擦 | 1.0 | 0.4 / 0.7 / 1.0 / 1.25 | 打滑、蹬地失效 |
| 接触刚度（solref） | 默认 | 软 / 中 / 硬 | 弹跳、穿透 |
| 控制延迟 | 0 ms | 0 / 5 / 10 / 20 ms | 相位滞后导致失稳 |
| 观测噪声 | 0 | 低 / 中 | 状态估计误差影响 |

每个配置跑 E={0..19} 共 20 episodes，记录：成功率、`vx_rmse`、**失败模式分布**（摔倒 / 打滑 / 执行器饱和 / 振荡 / 超时）。

**归因方法**：单因素主效应排序（按成功率下降幅度与 `vx_rmse` 增幅），找出 top-2 主因。

**补偿验证**：按主因做参数对齐（例如把 MuJoCo 的执行器 kp/kv 调到与 Isaac 等效、或加延迟补偿），复测并报告恢复幅度。

### 2.4 阶段 D：交付（约 3 天）

报告、README 首屏、一页式摘要、对比视频。

### 2.5 负结果也成立

如果迁移后成功率很低：**MVP 依然成立**，只要满足：

1. 损失被量化（成功率、误差、失败模式分布）；
2. 主因被归因（至少 3 个因素的敏感性）；
3. 补偿实验完成（哪怕补偿无效，无效本身是结论）；
4. 全程可复现。

MVP 承诺的是**方法闭环**，不是特定成功率。这一点必须在报告里写清楚，避免被结果绑架。

## 3. 最后得到什么成果

### 3.1 代码（公开仓库）

- `locomotion/sim2sim/`：MuJoCo 迁移环境、观测/动作对齐、命令序列生成
- `scripts/`：一键训练、导出、评估、敏感性扫描
- 每条命令可复现，CI 绿

### 3.2 数据与证据

- 3 份训练证据束（`run_config.json` + SHA-256 manifest）
- 迁移评估结果（每配置 20 episodes 的 CSV/JSON）
- 敏感性表与主因排序
- 补偿前后对比

### 3.3 报告

- **一页式技术摘要**：问题 / 方法 / 结果 / 归因 / 局限
- **迁移报告**：成功率、失败模式分布、主因、补偿效果、与真机的距离（诚实标注无真机）

### 3.4 演示

- 30–60 秒视频：同一条命令序列，Isaac 与 MuJoCo 并排对比
- 至少一个失败案例的慢放（面试时讲失败模式比讲成功更有说服力）

### 3.5 可讲的三句话

1. "我在 Isaac Lab 用冻结协议训练了 3 个种子的 Go2 速度跟踪策略，报告 mean±std，不做种子挑选。"
2. "我把策略零改动迁到 MuJoCo，量化了迁移损失，并把损失拆到执行器建模、接触参数和控制延迟上。"
3. "主因是 X，补偿后成功率从 A% 恢复到 B%；剩下的差距需要真机系统辨识才能继续收敛。"

## 4. 成功判据（Definition of Done）

**必须全部满足：**

- [ ] 3 个种子独立训练，证据束完整，报告 mean±std
- [ ] 迁移环境跑通，零权重改动
- [ ] 至少 3 个因素完成单因素扫描，每配置 20 episodes
- [ ] 给出主因排序与补偿前后对比
- [ ] 失败模式可分类（不是只报一个成功率）
- [ ] 一键复现命令 + 公开仓库 + CI 绿
- [ ] 一页式摘要 + 对比视频
- [ ] README 明确声明"无真机，迁移为仿真代理"

**期望（不作为成立条件）：**

- 迁移成功率 ≥ 70%，或补偿后恢复 ≥ 20 个百分点

## 5. 时间盒

| 周 | 内容 | 里程碑 |
| --- | --- | --- |
| W1 | 阶段 A：三种子训练 + 评估；阶段 B 起步（模型与关节映射） | 3 份证据束 + 评估报告初稿 |
| W2 | 阶段 B 完成：策略导出、观测/动作对齐、迁移评估跑通 | MuJoCo 能载入策略并跑完 20 episodes |
| W3 | 阶段 C：敏感性扫描 + 归因 + 补偿验证 | 敏感性表 + 主因结论 |
| W4 | 阶段 D + 缓冲：报告、README、视频、演练 | MVP 冻结，只修不建 |

**超时规则**：W2 结束仍无法在 MuJoCo 跑通 → 立即启用降级方案（见 §7），不在迁移环境上继续消耗时间。

---

## 6. MVP 边界（不做）

- ❌ 真机部署与 sim2real 实证
- ❌ 视觉/感知/VLA
- ❌ 奖励函数消融（P2，MVP 后）
- ❌ C0 基线归因（P3，MVP 后）
- ❌ S2 扰动训练（只在敏感性里覆盖摩擦/推挤）
- ❌ S3 楼梯、多机、算法创新、论文投稿

---

## 7. 风险与降级

| 风险 | 降级方案 |
| --- | --- |
| MuJoCo Go2 模型或关节映射阻塞 | 降级为**Isaac 内执行器参数扫描**（改变 kp/kv/延迟），问题改为"策略对执行器建模的敏感性"；仍是 sim2real 相关，仍可归因 |
| 策略导出失败 | TorchScript → ONNX → 手工重建 MLP（权重从 checkpoint 读出） |
| 迁移成功率过低 | 转为"差距分析"报告：失败模式 + 主因 + 补偿尝试，MVP 仍成立 |
| 敏感性实验过多 | 只做 3 个因素（kp、摩擦、延迟），其余列为未来工作 |
| 时间不足 | 保 P0 + 一页摘要 + 视频；敏感性降到 2 个因素 |

---

## 8. 与完整路线图的关系

本 MVP = [ROADMAP.md](ROADMAP.md) 的 **P0 + P1 + P1b + P4**。

P2（奖励消融）与 P3（C0 归因）不在 MVP 内，属于 MVP 完成且有余力时的增量。
