## 4. 过程记录规范（展示用）

**原则**：记录在事情发生时写，不事后补；失败也记录；每条结论能指向一个产物。

### 4.1 记什么

| 类型 | 频率 | 内容 | 位置 |
| --- | --- | --- | --- |
| **每日日志** | 每个工作日 | 目标 / 实际完成 / 决策 / 失败与修正 / 数据产物 / 明日计划 | `docs/journal/YYYY-MM-DD.md` |
| **架构决策（ADR）** | 每个不可逆决策 | 背景 / 选项 / 决定 / 后果 | `docs/decisions/ADR-NNN-<slug>.md` |
| **实验记录** | 每个实验 | 配置、命令、结果、异常、结论 | 随 run 的证据束 + `reports/guardrail/` |
| **失败记录** | 每次失败 | 现象、尝试、根因、修正 | 当日 journal + 报告"负结果"段 |
| **进度看板** | 每完成一项 | 里程碑状态、当前任务、阻塞 | `docs/PROGRESS.md`（单一入口） |
| **产物索引** | 每个里程碑 | 命令 + 产物路径 + 数据摘要 | 看板中每项一行 |

### 4.2 展示导向的三条硬要求

1. **每个里程碑留"证据卡"**：一条可复现命令、一个产物路径、一段数据摘要、一张截图（如适用）。
2. **时间线可回放**：`docs/journal/` 按日期排列，最终可直接汇总成"项目过程时间线"用于展示。
3. **失败与修正必须出现**：报告中保留负结果与失败尝试，这比只写成功更可信。

### 4.3 日志模板（`docs/journal/_TEMPLATE.md`）

```markdown
# YYYY-MM-DD

## 目标
## 实际完成
## 决策与理由
## 失败与修正
## 产物
| 产物 | 路径 | 命令/说明 |
## 明日计划
## 耗时（可选）
```

### 4.4 记录检查（每周）

- [ ] 本周每个工作日有 journal
- [ ] 每个不可逆决策有 ADR
- [ ] 每个实验有证据束（`run_config.json` + manifest）
- [ ] 看板与 journal 一致，无"已完成但无产物"的项
- [ ] 有至少一条失败记录及其修正

## 5. 工作方式

1. **单个任务闭环**：定验收 → 实现 → 验证 → 记录 → 提交推送（自动同步）。
2. **不跳过验证**：数值没对齐不接集成；测试没绿不进入下一任务。
3. **提交粒度**：一个任务一个提交，提交信息写明"做了什么 + 验证了什么"。
4. **每日收尾**：写 journal、更新看板、推送。

## 7. 风险与止损

| 风险 | 触发信号 | 止损动作 |
| --- | --- | --- |
| C++ 动力学实现错误 | 与 Isaac 对比误差超标 | 停在数值验证阶段，先修模型，不接集成 |
| 批量接口性能不达标 | 基准 > 1 ms/step | 批量化重写；仍不行则降采样仲裁（每 2 步）并记录 |
| 仲裁导致成功率大跌 | H1 不成立 | 报告 Pareto 曲线，把"约束的代价"作为结论 |
| RNID 超时 | W2 中未完成 | 降级 PD 力矩限幅，记录决策 |
| 训练不达标 | 三种子未过阈值 | 用官方超参复现后调；如实报告 |
