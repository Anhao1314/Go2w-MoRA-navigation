## 0. 能力模型（本阶段要对标的要求）

按足式机器人运动控制 / 强化学习岗位的实际要求整理，权重从高到低：

| 能力项 | 权重 | 本仓库怎么证明 |
| --- | --- | --- |
| RL 训练管线（从零搭建，不只是调参） | 必备 | `locomotion/` + `scripts/train_locomotion.py` + 每 run 证据束 |
| 仿真平台（Isaac Lab / MuJoCo） | 必备 | Isaac Lab 2.7.0 训练栈、MuJoCo 复刻（P1） |
| **Sim2Real 方法论**：域随机化、执行器建模、系统辨识、迁移归因 | **核心区分项** | P1：跨引擎迁移 + 执行器参数敏感性 + DR 消融 |
| 机器人学/动力学基础（FK/IK、MPC、欠驱动力学） | 必备 | C++ S0 栈（MPC/FK/IK 数值验证） |
| C++ / Python / Linux / ROS2 | 必备 | C++ 控制栈；ROS2 为设计文档（P1 未实现，需诚实标注） |
| 奖励函数与课程设计（面试高频追问） | 高 | P2：关键奖励项消融 + 设计理由 |
| 工程能力（Git / TensorBoard / Hydra / CI） | 中 | 预注册协议、证据链、GitHub Actions |
| 真机部署 | 高（多数岗位偏好） | **本阶段不具备**，见 §1 约束 |
| 论文 / 竞赛 | 加分 | 本阶段不产出 |

**判断**：前六项可以直接支撑面试；"真机"这一项无法补，只能用跨引擎迁移作为仿真代理，并在讲述时明确边界。

## 1. 北极星目标与约束

> **在 2026-11-20 前，产出一个能通过技术追问的运动控制 RL 作品集：三种子训练结果达标、完成一次跨引擎迁移并归因主导因素、用消融回答奖励设计问题，全程可复现。**

区别于"跑通 demo"的三条硬标准：结果带统计（三种子）、结论带归因（不是单个数字）、过程可复现（证据束 + 一键命令）。

**已知约束（必须诚实写入所有产出）**：

1. **无真机**。Sim2Real 以"跨物理引擎迁移（Isaac → MuJoCo）+ 执行器参数敏感性"作为仿真代理。它能暴露执行器建模、接触参数、控制延迟的影响，但不能替代真机验证；讲述时必须说明这是代理，不是 sim2real 实证。
2. **一人、一个月、单卡 RTX 5060 Ti 16 GB**。训练预算约 43 min/seed（1500 iters, 2048 envs，已实测），所以消融实验数量必须受控。
3. **本科在读**。目标岗位多数写硕士及以上，因此证据必须"可验证"：公开仓库、绿的 CI、一键复现、可播放的演示。

## 2. 目标优先级（时间不够时从上往下砍）

| 优先级 | 目标 | 交付物 | 预算 |
| --- | --- | --- | --- |
| **P0** | S1 平地速度跟踪，3 个独立种子达到协议阈值 | 3 份证据束 + 评估报告（mean±std）+ 演示视频 | 2–3 天（训练 ~2.2 h） |
| **P1** | Sim2Real 仿真代理：Isaac → MuJoCo 零策略改动迁移 | 迁移报告：成功率、失败模式、主导因素归因 | 4–6 天 |
| **P1b** | 执行器与域随机化敏感性：stiffness/damping/armature/latency 扫描；DR-off vs DR-on | 敏感性表 + DR 消融（2 个训练种子） | 3–4 天 |
| **P2** | 奖励设计消融：2–3 个关键奖励项的影响 | 消融表 + 每项的设计理由 | 2–3 天 |
| **P3** | C0 scripted PD 基线归因（同种子配对） | 配对差值表 | 2–3 天 |
| **P4** | 作品集包装：README 首屏、结果表、视频、一页式技术摘要 | 3 分钟可讲完的仓库入口 | 贯穿 |

**砍单顺序**：P3 → P2 → P1b → P1。P0 与 P4 不可砍。

**P1 与 P1b 的关系**：若 MuJoCo 迁移阻塞（模型/导出问题），P1b 仍可独立完成并在 Isaac 内做参数扫描，交付不归零。

## 3. 四周时间表（2026-10-23 起）

| 周 | 日期 | 交付物 | 周验收标准 |
| --- | --- | --- | --- |
| **W1** | 10/23–10/29 | S1 三种子训练（seed 0/1/2）；评估脚本接入 `locomotion/eval`；评估报告初稿 | 3 份 `run_config.json` + manifest；三种子在冻结种子 E={0..19} 上跑出 `vx_rmse`/`ωz_rmse`/`fall_rate` |
| **W2** | 10/30–11/05 | P1：MuJoCo Go2 模型接入、策略导出、跨引擎评估；Play 视频 | 零改动策略在 MuJoCo 跑通；给出成功率与失败模式；视频可播 |
| **W3** | 11/06–11/12 | P1b：执行器/延迟/摩擦敏感性 + DR 消融；P2：奖励消融 | 敏感性表能指出主导因素；DR-off 与 DR-on 各 1 种子对比 |
| **W4** | 11/13–11/19 | P3（可选）+ README 作品集化 + 面试演练 | README 首屏 30 秒能看懂；3 分钟讲述不卡壳；每个结论有产物指向 |
| 缓冲 | 11/20–11/23 | 只修不建 | 冻结状态 |

**W1 已完成的前置条件**（2026-10-23）：

- 训练链路打通：S1/S2/S2b 三配置可解析，`gym.make` + reset + step 通过，obs `(N, 48)`
- 吞吐基准：2048 envs × 20 iters = 34.36 s，显存峰值 4208 MiB → 1500 iters ≈ 43 min/seed
- 每 run 证据束：`run_config.json`（git SHA / dirty / 依赖版本 / 命令行 / seed）+ `sha256_manifest.json` 自动生成

## 4. 验收标准（Definition of Done）

- [ ] S1 三种子各自独立训练，证据束完整（含 git SHA、依赖版本、命令行）
- [ ] 报告 `vx_rmse` 与 `ωz_rmse` 的 mean ± std；**禁止只报最好种子**
- [ ] 达阈值（`vx_rmse ≤ 0.15 m/s`、`ωz_rmse ≤ 0.2 rad/s`）或明确报告未达标与原因
- [ ] 评估固定使用冻结种子集 `E={0..19}`，指标复用 `locomotion/eval/metrics.py`
- [ ] 跨引擎迁移报告写明：成功率、失败模式（摔倒/打滑/执行器饱和）、主导因素
- [ ] 执行器敏感性至少覆盖 stiffness、damping、控制延迟三项
- [ ] 奖励消融至少 2 项，每项给出对速度跟踪或步态的影响
- [ ] 至少一段 30–60 秒演示视频
- [ ] `python scripts/eval_protocol.py --verify` 通过；CI `tests-and-types` 绿
- [ ] README 首屏包含：一句话定位、结果表、演示入口、**局限声明（无真机）**

## 5. 明确不做

- ❌ 真实机器人部署（无硬件）
- ❌ 视觉/感知输入、VLA、语言指令
- ❌ 新算法研究（PPO/RSL-RL 足够；本项目做归因与迁移，不做算法创新）
- ❌ 论文投稿、竞赛（窗口内不可行）
- ❌ S3 楼梯课程、多机协同
- ❌ Phase-1（Go2W 导航）的功能演进

## 6. 风险与预案

| 风险 | 影响 | 预案 |
| --- | --- | --- |
| ~~显存不足~~ | — | **已排除**：峰值 4208 MiB（实测） |
| MuJoCo Go2 模型或策略导出阻塞 | P1 停摆 | 先做 P1b（Isaac 内参数扫描）；P1 降级为"仿真内的执行器建模分析" |
| 训练不达标 | P0 失败 | 用官方超参复现后再调；不达标也如实报告并给出失败分析 |
| 消融实验数量过多拖垮排期 | 全线延期 | 每个消融只跑 1 个种子，明确标注"单种子，不作统计推论" |
| 本科简历筛选被卡 | 无面试机会 | 用可验证产物补位：公开仓库、绿 CI、一键复现、视频、技术摘要；投递时优先本科可投与实习岗 |
| 时间被压缩 | 全线延期 | 按 P3 → P2 → P1b → P1 砍，保 P0 + P4 |

## 7. 讲述要点（按面试高频问题组织）

每个问题都要能落到代码、数据或报告，不能只讲概念。

| 问题 | 回答要点 | 证据位置 |
| --- | --- | --- |
| 仿真和真机差距怎么解决？ | 承认无真机；用 Isaac→MuJoCo 跨引擎迁移暴露执行器建模与接触参数的影响，并量化主导因素；上真机后的第一步是系统辨识（参数扫描 + 拟合响应） | P1 报告 |
| 奖励函数怎么设计？ | 不照搬默认：给出 2–3 项消融，说明每项对速度跟踪/步态的作用，以及去掉后的退化 | P2 消融表 |
| 为什么用 PPO？ | 在线 + 大规模并行 + RSL-RL 生态 + 与 Isaac Lab 集成成熟；SAC 等 off-policy 在 2048 并行下样本效率优势不显著 | 训练配置 |
| 域随机化范围怎么定？ | DR-off vs DR-on 消融 + 范围敏感性；说明当前范围是官方默认，未做真机标定 | P1b |
| 怎么保证不是过拟合评估种子？ | 训练种子与评估种子分离；三种子报告；预注册协议禁止只报最好种子 | `EXPERIMENT_DESIGN.md` §3 |
| C++/ROS2 到什么程度？ | C++ S0 栈（MPC/FK/IK）有数值验证；ROS2 仅架构设计未实现（诚实说明） | `cpp/`、`docs/CPP_ROS2_ARCHITECTURE.md` |
| 你的项目边界是什么？ | 仿真限定、无真机、盲观测、无感知；成功标准是三种子达标 + 归因，不是"通用运动智能" | README 局限声明 |
