# 项目目标与路线图（2026 Q4）

[返回首页](../README.md) · [文档索引](README.md) · [实验协议](EXPERIMENT_DESIGN.md)

## 0. 北极星目标

> **在 2026-11-20 前，把本仓库从「Phase-1 已完成 + Phase-2 骨架」推进到「一个可复现、可归因、可现场演示的完整研究闭环」——用冻结协议训练出达标的 Go2 关节级运动策略，量化 RL 相对传统控制基线的增量，并留下能支撑技术深挖的证据链。**

一句话版本：**不是"跑通了一个 RL demo"，而是"独立走完了一次从协议设计到结论归因的研究"。**

## 1. 要证明的四项能力

| 能力 | 仓库中的证据 | 现状 |
| --- | --- | --- |
| **实验方法论**：预注册协议、冻结种子、负结果保留、变更留痕 | `docs/EXPERIMENT_DESIGN.md`（v1.0 冻结）、`scripts/eval_protocol.py --verify`、`reports/` 失败实验归档 | ✅ 已有，稀缺项 |
| **RL 训练工程**：Isaac Lab 大规模并行、PPO、域随机化、课程/消融 | `locomotion/isaac/`（S1/S2/S2b 三场景注册）、3 种子训练 + 20 episode 评估 | ⏳ M1 待产出 |
| **控制理论深度**：能解释 RL 为什么有效，而不只是调包 | C++ S0 栈（FK/IK/MPC 数值验证）、C0 scripted PD 基线、RL vs C0 同种子配对对比 | 🟡 栈已有，基线待接入 |
| **系统工程**：CI、证据束、一键复现、模块边界契约 | GitHub Actions、SHA-256 证据清单、`docs/ARCHITECTURE.md` 布局契约、导入顺序契约 | ✅ 已有，持续维护 |

**差异化定位**：应届项目里"用 Isaac Lab 训一个 Go2 走起来"并不稀缺；稀缺的是**做这件事时的方法论**——先冻结评估口径再训练、保留负结果、把每个结论绑定到可复核的产物。四项能力里第 1、4 项是护城河，第 2、3 项是门票。

## 2. 目标优先级（时间不够时从上往下砍）

| 优先级 | 目标 | 交付物 | 预计投入 |
| --- | --- | --- | --- |
| **P0** | M1-S1：平地速度跟踪，3 个独立种子达到协议阈值 | 3 个 `run_config.json` + 评估报告 + 讲解视频 | 3–5 天（含训练 3–4 h） |
| **P1** | RQ2 归因：RL vs C0 scripted PD，同种子配对 | 归因报告（含配对差值、符号不设限） | 3–4 天 |
| **P2** | S2 扰动：至少 1 个 DR 种子的扰动恢复评估 | 扰动评估报告（no-fall ≥ 90% 为达标线） | 3–5 天 |
| **P3** | S4 Sim2Sim：Isaac → MuJoCo 零改动策略 | Sim2Sim 报告（成功率 ≥ 90%） | 5–8 天（预算门控，可不做） |
| **P4** | 作品集包装：README 入口、一页式结果、演示视频 | 3 分钟能讲完的仓库入口 | 贯穿全程 |

**砍单顺序**：P3 → P2 → P1。P0 和 P4 不可砍。

## 3. 四周时间表（2026-10-23 起）

| 周 | 日期 | 交付物 | 周验收标准 |
| --- | --- | --- | --- |
| **W1** | 10/23–10/29 | 吞吐基准（2048 envs 显存/速度实测）；S1 三种子训练；评估脚本接入 `locomotion/eval` | 3 份 run 目录完整；评估能在冻结种子上跑出 `vx_rmse`/`ωz_rmse`/`fall_rate` |

| **W3** | 11/06–11/12 | RQ2 归因报告；S2 扰动（DR-on 种子 + 扰动评估）；README 作品集化 | 归因表给出配对差值；README 首屏 30 秒能看懂项目价值 |
| **W4** | 11/13–11/19 | 缓冲：补实验、修文档、面试演练 | 四项能力各有可指认的证据；3 分钟讲述不卡壳 |
| 缓冲 | 11/20–11/23 | 只修不建 | 冻结状态，不再开新实验 |

**W1 第一天基准（2026-10-23 实测，RTX 5060 Ti 16 GB）**：`--num_envs 2048 --max_iterations 20` 用时 **34.36 s**（≈1.72 s/iter），显存峰值 **4208 MiB**。外推：1500 iters ≈ **43 min/seed**，3 个独立种子 ≈ **2.2 h**（不含评估）。16 GB 显存余量充足，协议要求的 2048 envs **无需降档**，P0 排期成立。

基准练习同时暴露了开跑前必须补齐的一项协议要求：每次训练需按 [EXPERIMENT_DATA.md](EXPERIMENT_DATA.md) 生成 run 证据束（`run_config.json` 含 git SHA / 依赖版本 / seed / 命令行，外加 SHA-256 清单）。此项应在第一个种子开跑前完成，否则 P0 的产物不满足冻结协议 §7。

## 4. 验收标准（Definition of Done）

- [ ] S1 三种子各自独立训练（不同 seed），`run_config.json` 含 git SHA、依赖版本、命令行
- [ ] 三个种子均报告 `vx_rmse` 与 `ωz_rmse`，按 mean ± std 汇总；**禁止只报最好种子**
- [ ] 达阈值（`vx_rmse ≤ 0.15 m/s`、`ωz_rmse ≤ 0.2 rad/s`）或明确报告未达标及原因
- [ ] 20 episode 评估使用冻结种子集 `E={0..19}`，指标复用 `locomotion/eval/metrics.py`
- [ ] C0 基线与 RL 策略在**相同种子、相同指标**下配对对比，差值量化、符号不设限
- [ ] 至少一段 30–60 秒演示视频（Play 任务，命令变化可见）
- [ ] `python scripts/eval_protocol.py --verify` 通过；CI `tests-and-types` 绿
- [ ] README 首屏可见：项目一句话、当前结果表、演示入口、证据链接

## 7. 讲述要点（面试时按需展开）

**30 秒**：这是一个 Unitree Go2 的关节级 RL 运动控制项目。我先冻结了评估协议——20 个评估种子、两个跟踪指标、明确阈值——再开始训练，所以结果是可复核的。三个独立种子达到平地速度跟踪阈值，并且我用同种子的 scripted PD 基线量化了 RL 的增量。

**3 分钟**：从"为什么先协议后训练"讲起——大多数 demo 的 20/20 成功率来自挑选种子；我用预注册把这条路堵死。然后讲训练栈（Isaac Lab、RSL-RL PPO、2048 并行、盲观测 48 维）、三个种子的一致性、C0 基线的配对对比，最后讲局限：仿真限定、无感知、没有真机。

**深挖准备**（每个都要能落到代码或数据）：
- 为什么用 PPO 而不是 SAC/TD3？→ 在线、大规模并行、稳定性；RSL-RL 生态
- 盲观测 48 维怎么来的？→ 实测项与维度，见 `velocity_env_cfg.py`
- 域随机化贡献怎么量化？→ S2 消融设计（DR-off / DR-on）
- 怎么保证不是过拟合评估种子？→ 训练种子与评估种子分离；三训练种子报告
- 负结果有哪些？→ DAgger 0% 历史实验、M2.0 失败案例
- C++ 控制栈与 RL 什么关系？→ S0 可验证控制 + C0 基线，用传统控制给 RL 定标尺
