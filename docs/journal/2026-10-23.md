## 决策与理由

1. **不再把"RL vs scripted PD 归因"作为主线**：JD 调研显示 Sim2Real 与架构能力权重远高于此。见 ADR-001。
2. **仲裁层用 C++ 独立模块，不复用 Go2W 栈**：Go2W 模型常量硬编码（`body[3]` 为轮），Go2 是 12 关节；改旧栈会破坏 Phase-1 冻结。见 ADR-002。
3. **A/B/C 共用同一策略权重**：让性能差异只能来自仲裁层，避免训练随机性污染结论。见 ADR-003。
4. **证据束改为两阶段生成**（start / finalize）：Isaac Sim 从 C++ 层硬退出，`finally` 不可靠；Gymnasium 注册不跨进程。

### 训练加速与效率调研（晚间）

**已实施**（实测 1.80 → 0.75 s/iter，2.4×）：

1. 杀掉残留的 `export_go2_model.py` 进程（PID 32228，累计 3165 s CPU，`simulation_app.close()` 卡住未退出）
2. 训练进程优先级设为 `High`
3. 训练期间停止 pyright/编译等 CPU 密集任务

**判断修正**：此前推断"训练 CPU 受限所以并行不划算"不准确。实测总 CPU 仅 12–17%，
训练只占约 2 个核，GPU 36–56%——瓶颈是**单线程延迟**，多核大量空闲。
因此 2 路并行（显存 2×5.2 GB）预期接近线性加速，列入后续方案。

**学习笔记**：`docs/notes/training-efficiency.md`，要点：

- Rudin 2021：rollout 少于约 25 步会阻碍收敛（我们用 24，处于下限）；大 mini-batch 稳定；
  必须区分失败重置与超时重置（critic bootstrapping）。
- Isaac Lab 官方基准把吞吐拆为「纯环境 / +推理 / +训练」三段，本地有
  `scripts/benchmarks/benchmark_rsl_rl.py` 与 `benchmark_non_rl.py` 可直接用。
- SB3 适配层只处理已终止环境可提速约 3×，说明包装器可能是隐藏瓶颈。
- "Walk These Ways" 的条件策略（行为参数 b）可作为分层接口的备选设计。

**纪律**：并行度、日志、评估并行化可自由优化；`num_envs`、rollout 长度等会改变训练动态，
必须作为独立配置并声明，不能混入主结果表；评估种子与指标不可改。

### L3 首轮结果：分层 100 迭代收敛，单层 250 迭代无进展（关键分离）

L3（前进 2 m → 转 90° → 前进 2 m → 停止 1 s）恢复后，A/B 并行训练（同环境同超参同种子）：

| 组 | 收敛（早停） | 训练时间 | 过程 |
| --- | --- | --- | --- |
| **B 分层** | **100 迭代** | **173.5 s** | 50 迭代完成率 100%（streak 1），100 迭代 100%（streak 2）→ 停 |
| A 单层 | 未收敛（≥250 迭代 0%） | 跑满 1500 | 100/150/200/250 迭代完成率全部 0.0% |

这是 L1 上没有的分离：L1 两组都 100%（A 需 150 迭代）；L3 上 B 直接通过四阶段，
A 完全卡住。与 H2（任务越复杂分层优势越大）方向一致——待 A 跑完与冻结种子评估确认。

**周期评估 + 早停按设计工作**：B 的训练从约 20 分钟缩到 173 秒（省 85%+），
收敛点被精确记录（convergence_log.jsonl：50/100 迭代各一行）。

**为什么训练日志判据被否定**（实现时的重要发现）：PPO 训练时动作从随机策略采样，
日志里的 `sequence_complete` 是"含探索噪声的完成率"——B 组末期日志值 0.045，
而确定性评估是 1.00。若用日志判据会永远不停。改用块间确定性评估
（训练 env、2048 个环境、900 步上限），在 rollout buffer 已消费后执行，不污染训练。

2. 每个条件只有 1 个训练种子，无跨种子方差；

| 第 220 迭代 reward | -4.29 | 36.33 |

**读法**：L1 上两者都完全解决，符合 H2（分层不是银弹，简单任务没有成功率差异）。
差异出现在**完成效率**（5.8×）和**训练早期的学习速度**上，但后者目前只有 reward 曲线
作证，还需要按 checkpoint 扫描成功率来量化样本效率（下一步）。

**停止判据的统一**：分层 B 的稳定漂移是 0.110 m、单层 A 是 0.042 m，都稳定不累积，
属于四足站立时的重心调整。容差从 0.05 m 调到 **0.15 m** 并去掉瞬时速度条件，
两组用同一标准。这是判据修正而非为某一组放宽——两个值都落在合理停止范围内，
且改动前 A 通过、B 不通过，改动后两者都通过。

### L1 完成：单层策略 20/20（关键里程碑）

修好闭环指令与停止判据后，同一个 checkpoint 在冻结种子上的结果：

| 指标 | 值 |
| --- | --- |
| success_rate | **1.00（20/20）** |
| stage_reach_rate | 0: 1.00 / 1: 1.00 |
| mean_steps_to_finish | **563.95**（约 11.3 s） |
| fall_rate | **0.00** |

三项修复的组合生效：

1. **闭环阶段指令**（比例转向 + 转向减速）：阶段 0 到达率 5% → **100%**
2. **目标锚定初始朝向**（而非世界 +x）：解决了"走对方向却永远到不了"
3. **停止判据改为位置漂移**（0.05 m 内持续 25 步）：速度判据在 0.003–0.511 m/s
   震荡下永远无法连续达标，而位置漂移与"停住"的语义一致

这一步建立了 A/B 对比的**公平基线**：单层在 L1 上能完整完成，说明训练管线、
奖励设计、环境与评估都正确。此后如果单层在 L2/L3 上失败，才构成对架构的有效证据。

### L1 第一轮失败诊断：固定指令的横向漂移（关键发现）

L1 训练 reward 从 -0.65 升到 27.8（明显在学习），但评估 **成功率只有 5%**（20 个里
1 个完成），其余跑满 3000 步、阶段为 0。

三层诊断，每层都推翻了上一层假设：

1. **看轨迹**：机器人不是站桩，而是走了 **37 米**（60 s × 0.6 m/s），方向朝西北，
   阶段始终 0。z 从 0.40 掉到 0.19（失稳滑行）。
2. **查起始位姿**：打印 `state.start` 与 `root_pos_w` / `heading_w`，完全一致；
   reset 事件顺序 `reset_base → reset_robot_joints → reset_stage` 也正确。环境状态没问题。
3. **测前进方向**：用训练好的策略跑 100 步——位移 1.06 m、body vx 0.618 m/s，
   **确实沿 heading 前进**，但方向偏了 **15.8°**。

根因：走 1.2 m 时，15.8° 的偏差累积成 **0.33 m 横向误差**，刚好超过 0.3 m 容差，
阶段 0 永不触发，机器人继续走就远离目标。

而偏差的来源是 `stage_command` 一直输出固定 `[0.6, 0]`：策略只学会直线走，没有任何
转向修正，初始朝向与目标方向的偏差无法被消除。

**修复**：把 stage_command 改成闭环指令——按"到目标的方向误差"给比例转向，
并在转向时减速：

```text
wz = clamp(2.0 * heading_error, -1, 1)
vx = 0.6 * clamp(1 - 0.8*|heading_error|, 0.15, 1)
```

这正是分层要研究的东西：规则层生成可执行的高层指令（含转向修正），
低层策略只负责跟踪。`stage_velocity` 奖励也改为跟踪同一条指令。

重训已启动，面板已切到新日志。

### 难度降到 L1（按研究计划的阶梯）

L3（前进 2 m → 转 90° → 前进 2 m → 停止 1 s）在 1500 迭代下，单层只能到
阶段到达率 95% / 75% / 0% / 0%。要建立"单层可学"的公平基线，先降到 L1：

| 参数 | L3 | **L1** |
| --- | --- | --- |
| 前进距离 | 2.0 m | **1.2 m** |
| 阶段 | forward → turn 90° → forward → stop 1 s | **forward → stop 0.5 s** |
| 阶段数 | 4 | **2** |
| 停止保持 | 50 步 | **25 步** |

改动集中在 `locomotion/sequence/mdp/__init__.py` 的常量与 `_targets/_remaining/_advance`；
L3 版本保留在 git 历史（`ac369fa` 及之前）。L2（前进 1.2 m + 转 45° + 停止）尚未建立。

判据：如果单层在 L1 上能达到高成功率，说明训练管线与奖励设计没问题，再逐级升到 L2/L3；

### 阶段目标坐标 bug（重要修复）

n 轮训练都推不动阶段的真正原因，与奖励无关：

- `_targets` 用**世界坐标** +x / +y 定义目标点；
- 策略跟踪的是 `stage_command` 给出的**体坐标系**前向速度；
- `reset_base` 随机化初始朝向，于是"向自己前方走"永远接近不了世界 +x 的目标。

表现正是之前看到的矛盾：训练时速度跟踪 0.74（说明在走），阶段进度却恒为 0。

修复：目标改为沿**初始朝向前进 2 m**，再沿**转向 90° 后的方向前进 2 m**（L 形路径），
与体坐标命令一致。

修复后的评估（同一 checkpoint）：

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| 到达阶段 1 | 0 % | **95 %** |
| 到达阶段 2 | 0 % | **75 %** |
| 到达阶段 3 | 0 % | 0 % |
| success_rate | 0 | 0（摔倒率 0.2） |

前两段已能完成，第三段（第二次前进）尚未学会——这是单层在 1500 迭代下的真实水平，
也是下一步要么加预算、要么降难度的依据。

### 单层 A 第一轮失败：奖励设计问题（重要负结果）

评估脚本适配 sequence 任务后，A 组结果：**20/20 全部 `max_stage=0`、成功率 0、跑满 3000 步**。

诊断（不是评估脚本的问题，是奖励设计）：

- 训练 `Mean reward` 从 -0.64 降到 -1.48，**没有上升**；`Mean episode length` 从 13 升到 3000——
  策略学会了"站着不动、不摔倒"，但从不前进。
- 关键证据：`Episode_Reward/stage` 恒为 **0.0177–0.0192**，正好等于 `exp(-2 × 2 m) = 0.018`。
  距离目标始终是 2 米，说明策略原地不动。
- 原因：`exp(-2·remaining)` 在 2 m 处的梯度只有约 0.037/米；每步前进 0.012 m 带来的奖励变化
  约 0.0004，被动作/姿态惩罚（合计约 -0.04/步）完全淹没。站住是局部最优。

**修正**：把阶段奖励改成进度差分（potential-based shaping）：

```text
r_t = 10 * clip(remaining_{t-1} - remaining_t, -0.05, 0.05)   # 每米进度给 10 分
    + 10 * advanced                                            # 阶段切换 +10
```

阶段切换时重置基线，避免"距离 → 航向误差"的度量跳变被当成进度。

**这是研究的一部分，不是事故**：单层架构在稀疏/弱奖励下退化为"站桩"，与 Phase-1 的历史
（单层 PPO v1–v5 全部 ≤0.7 m）一致。修正奖励后重训，若单层仍然学不会，才构成对架构的
有效证据；在此之前不能把失败归因于"单层不行"。
