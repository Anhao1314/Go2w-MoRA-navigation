## 0. 能力模型（本阶段要对标的要求）

按足式机器人运动控制 / 强化学习 / 具身架构岗位的实际要求整理，权重从高到低：

| 能力项 | 权重 | 本仓库怎么证明 |
| --- | --- | --- |
| RL 训练管线（从零搭建，不只是调参） | 必备 | `locomotion/` + `scripts/train_locomotion.py` + 每 run 证据束 |
| 仿真平台（Isaac Lab / MuJoCo） | 必备 | Isaac Lab 2.7.0 训练栈 |
| **系统架构与可验证性**：分层接口、运行时约束、失败可归因 | **核心区分项** | 架构 v0.2：可验证仲裁层 + A/B/C 对照实验 |
| 机器人学/动力学基础（FK/IK、MPC、欠驱动力学） | 必备 | C++ S0 栈（MPC/FK/IK 数值验证）+ 仲裁规则基于物理量 |
| C++ / Python / Linux / ROS2 | 必备 | **C++ 仲裁核心**：浮基 FK、CoM/支撑多边形、摩擦锥、RNID；pybind11 批量接口 + Catch2 测试 + 性能基准；ROS2 为设计文档（未实现，需诚实标注） |
| 实验方法论：预注册、冻结种子、负结果保留 | 高 | 协议 v1.0 + `eval_protocol.py --verify` |
| 工程能力（Git / TensorBoard / Hydra / CI） | 中 | 证据链、GitHub Actions |
| Sim2Real / 真机 | 高（多数岗位偏好） | 本阶段不做；跨引擎迁移列为可选（P3） |
| 论文 / 竞赛 | 加分 | 本阶段不产出 |

**判断**：纯 RL 训练同质化严重；本仓库的差异化是**分层架构 + 可验证控制**。因此本阶段主线放在架构验证（可验证仲裁层），而不是追求更高的训练成功率。跨引擎迁移降为可选加分项。

## 1. 北极星目标与约束

> **在 2026-11-20 前完成一次架构验证：在 MoRA 的 S1 与 S0 之间引入可验证仲裁层，用 A/B/C 对照实验回答「可验证约束能否在不显著损失性能的前提下降低危险状态发生率」，全程可复现。**

区别于"跑通 demo"的三条硬标准：结果带统计（三种子 + 三场景）、结论带归因（触发分布解释失败模式）、过程可复现（证据束 + 一键命令）。

**已知约束（必须诚实写入所有产出）**：

1. **无真机**。仲裁层在仿真中验证；讲述时必须说明"可验证约束"的结论适用于仿真，真机还需系统辨识与硬件在环。
2. **一人、一个月、单卡 RTX 5060 Ti 16 GB**。训练预算约 43 min/seed（已实测）；A/B/C 共用同一策略权重，只改仲裁层，因此实验成本主要在评估而非训练。
3. **本科在读**。目标岗位多数写硕士及以上，因此证据必须"可验证"：公开仓库、绿的 CI、一键复现、可播放的演示。

## 2. 目标优先级（时间不够时从上往下砍）

| 优先级 | 目标 | 交付物 | 预算 |
| --- | --- | --- | --- |
| **P0** | S0 基线：平地速度跟踪，3 个独立种子达到协议阈值（分层组的 S0 + 单层组的子技能） | 3 份证据束 + 评估报告（mean±std） | 进行中（每种子约 20 min） |
| **P1** | 命令序列任务环境（四阶段，含阶段成功判据） | `locomotion/sequence/` + 环境测试 | 3–4 天 |
| **P2** | 单层基线 A：观测+阶段 → 12 维关节 | 训练证据束 + 成功率/样本效率曲线 | 3–5 天 |
| **P3** | 分层 B：S2 规则 + S1 策略 + S0（P0 策略） | B 组结果 + A/B 对比表 | 4–6 天 |
| **P4** | 泛化与失败归因：未见序列、S1 决策错 vs S0 执行失败 | 归因表 + 报告 + 视频 | 3–4 天 |
| **P5** | 层间约束子研究（可选）：C 组 = B + C++ 物理仲裁 | 干预率/成功率权衡 | 预算门控 |

**砍单顺序**：P5 → P4 的泛化部分 → P3 的 S1 学习版（降级为规则 S1）。P0、A/B 对比不可砍。

**关键设计**：A 与 B 获得相同的任务信息（阶段/目标都可见），对比的是"显式分解"与"隐式学习切换"；S0 复用 P0 的策略权重，因此 P0 不会白跑。

## 4. 验收标准（Definition of Done）

- [ ] S1 三种子各自独立训练，证据束完整（含 git SHA、依赖版本、命令行）
- [ ] 报告 `vx_rmse` 与 `ωz_rmse` 的 mean ± std；**禁止只报最好种子**
- [ ] 达阈值（`vx_rmse ≤ 0.15 m/s`、`ωz_rmse ≤ 0.2 rad/s`）或明确报告未达标与原因
- [ ] 仲裁契约向后兼容：默认 `AllowAllArbiter` 不改变 v0.1 行为（有回归测试）
- [ ] C++ 浮基 FK 与 CoM 和 Isaac 的数值对比达标（位置 < 1e-4 m）
- [ ] 支撑多边形、摩擦锥、力矩检查均有边界单元测试；`CLAMP` 后动作满足约束（断言）
- [ ] 批量仲裁在 2048 envs 下 < 1 ms/step（有基准数据）
- [ ] C++ 核心与 Python 参考实现在同一组随机输入下结果一致
- [ ] A/B/C × 3 场景 × 20 episodes 完整，指标复用 `locomotion/eval/metrics.py`
- [ ] 报告回答 RQ1–RQ3（成立或不成立并解释），含干预率与性能损失的权衡曲线
- [ ] 阈值标定可复现（说明来自基线哪个分位数）
- [ ] 至少一段 30–60 秒对比视频（含仲裁触发时刻）
- [ ] `python scripts/eval_protocol.py --verify` 通过；CI `tests-and-types` 绿
- [ ] README 首屏包含：架构图、一句话结论、**局限声明（仿真限定、无真机）**

## 5. 明确不做

- ❌ 追求 SOTA 训练成功率（本项目做架构验证，不做性能竞赛）
- ❌ 真实机器人部署（无硬件）
- ❌ 视觉/感知输入、VLA、语言指令
- ❌ 新 RL 算法研究（PPO/RSL-RL 足够）
- ❌ 论文投稿、竞赛（窗口内不可行）
- ❌ S3 楼梯课程、多机协同
- ❌ Phase-1（Go2W 导航）的功能演进

## 6. 风险与预案

| 风险 | 影响 | 预案 |
| --- | --- | --- |
| ~~显存不足~~ | — | **已排除**：峰值 4208 MiB（实测） |
| 仲裁频繁触发导致成功率大跌 | P1b 结论难看 | 报告 Pareto 曲线；阈值上调至 99.9 分位；"性能损失"作为结果而非失败 |
| 阈值取自分位数对扰动场景过严 | 场景间不可比 | C 配置按场景缩放；报告中给出两套阈值 |
| 仲裁掩盖策略缺陷 | 结论失真 | 区分"被拦截的危险动作"与"策略本就不会做"；与 A 的失败样本对照 |
| 规则实现与仿真状态不同步 | 结果不可信 | 规则只读 observation/info，不读仿真内部对象 |
| 本科简历筛选被卡 | 无面试机会 | 用可验证产物补位：公开仓库、绿 CI、一键复现、视频、架构文档；投递优先本科可投与实习岗 |
| 时间被压缩 | 全线延期 | 按 P3 → P2 → P1b → P1 砍，保 P0 + P4 |

## 7. 讲述要点（按面试高频问题组织）

| 问题 | 回答要点 | 证据位置 |
| --- | --- | --- |
| 你的项目做了什么架构创新？ | 在分层架构的 S1 与 S0 之间加入可验证仲裁层，把安全性从"训练期望 + 事后停机"变成"运行时约束"；A/B/C 量化干预率与性能权衡 | `docs/ARCHITECTURE_V2.md` |
| 为什么用规则而不是学习一个安全策略？ | 规则可验证、可单测、可解释；学习型安全策略会引入新的不确定性，且难以证明边界 | 架构文档 §3 |
| 仲裁会不会让策略变"笨"？ | 报告 Pareto 前沿：干预率 vs 成功率损失；并区分被拦截的危险动作与策略本身不会做的动作 | P1b/P2 报告 |
| 阈值怎么定？ | 取基线策略统计分布的 99.5 分位，来源可复现；自适应阈值按命令速度/地形缩放 | P2 报告 |
| 为什么用 PPO？ | 在线 + 大规模并行 + RSL-RL 生态 + 与 Isaac Lab 集成成熟 | 训练配置 |
| 怎么保证不是过拟合评估种子？ | 训练/评估种子分离；三种子报告；预注册协议禁止挑最优 | `EXPERIMENT_DESIGN.md` §3 |
| C++ 到什么程度？ | 独立实现仲裁核心：浮基 FK、CoM/支撑多边形、摩擦锥、RNID 力矩可行性；pybind11 批量接口；Catch2 边界测试；与 Isaac 数值对比 + 2048 envs 性能基准 | `cpp/guardrail/` |
| 运动物理学具体用在哪？ | 支撑多边形判据判静稳定、摩擦锥判打滑、逆动力学判执行器可行性；阈值取自基线物理量分布的分位数 | `docs/ARCHITECTURE_V2.md` §3.1 |
| ROS2 到什么程度？ | 仅架构设计未实现（诚实说明）；仲裁核心按可移植 C++ 设计，未来可编译为 ROS2 节点 | `docs/CPP_ROS2_ARCHITECTURE.md` |
| 你的项目边界是什么？ | 仿真限定、无真机、盲观测；成功标准是架构假设的验证，不是通用运动智能 | README 局限声明 |
