# ADR-002：C++ 仲裁核心独立成模块，不复用 Go2W 栈

- **状态**：接受
- **日期**：2026-10-23
- **相关**：[架构 v0.2 §3](../ARCHITECTURE_V2.md#3-技术栈明确的分工)

## 背景

`cpp/` 已有浮基 FK、质心动力学、SRBD MPC 与安全状态机，但它们是为 **Go2W 轮足**写的：

- 模型常量由 `scripts/gen_model_constants.py` 生成并硬编码（`LegDef.body[3]` 直接是轮子）；
- 关节数、连杆树、动作维度（6 维：4 轮力矩 + 2 腿姿态）都按 Go2W 固定；
- Phase-1 已冻结，按布局契约不应继续演进。

而仲裁层需要 **Go2 的 12 关节**模型（每腿 hip/thigh/calf，无轮）。

## 选项

1. **改造现有 `cpp/` 支持双模型**：复用度最高，但要改动冻结区，且硬编码结构需要重构为通用连杆树，回归风险大。
2. **新建独立模块 `cpp/guardrail/`**：复用 Eigen、CMake 与测试习惯；模型参数改为运行时加载 JSON，不硬编码。
3. **用 Python 实现物理检查**：开发最快，但 2048 环境 × 50 Hz 的调用开销不可接受，且无法体现 C++ 能力。

## 决定

选择选项 2。`cpp/guardrail/` 作为独立 CMake target，只依赖 Eigen；模型参数从 Isaac 运行时导出为 JSON，启动时加载，并有一致性测试防止漂移。

## 后果

**正面**

- 不动 Phase-1 冻结栈，回归风险低。
- 模型参数化，未来可支持 Go1/H1 等其他机型。
- 可单独基准测试与单元测试。

**负面 / 风险**

- 需要重新实现 FK/RNID（不能直接复用 Go2W 的硬编码实现）。
- 导出参数与 Isaac 的模型必须保持一致，否则物理检查结论失真。

**跟进**

- W1.2 完成参数导出与一致性测试。
- W1.3 的 FK/CoM 必须先与 Isaac 数值对齐（< 1e-4 m）再接集成。
