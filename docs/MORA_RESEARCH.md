# MoRA 架构深度研究：公开资料还原、仓库差距分析与 MoRA-inspired v2 路线

**文档性质：** 公开资料研究 + 代码对照分析，不构成对 MoRA 官方实现的复现或逆向工程说明。

**研究日期：** 2026-10-19

**研究对象：**
- 墨奇智能（MORPHI）MoRA（MORPHI Reasoning & Autonomy）具身智能架构
- 本仓库 `Go2w-MoRA-navigation` 的 "MoRA-inspired" 分层实现

**一句话结论：** 本仓库目前借鉴的是 MoRA 的**三层职责划分**（规则决策 / 学习型导航策略 / 脚本运动控制），但没有实现 MoRA 真正的核心——**把目标持续性、多粒度记忆和进度认知内化到 System 1 策略内部**。仓库的 "记忆" 实际是环境侧手写状态机，"目标条件" 是少量数值特征拼接，"进度" 是环境计算的奖励塑形项。要推进到 MoRA-inspired v2，应优先做三件事：**内化记忆、加进度头、把外部状态从观测里拿掉并做消融**。

## 1. MoRA 是什么

### 1.1 背景

- **公司：** 墨奇智能（MORPHI），深圳，2026 年成立，联合创始人高文礼、CTO 黄青虬（前华为 "天才少年"，清华自动化本科、港中文 MMLab 博士）。
- **模型：** MoRA = **MORPHI Reasoning & Autonomy**，2026 年 8 月 WRC 首次公开。
- **本体：** MORPHI KINO，轮式双臂家庭服务机器人。
- **演示：** 约 15 分钟连续家庭任务，覆盖桌面清理、冰箱盘点补货、衣物洗烘折叠，约 70–80 个连续动作，全程端侧模型自主执行。
- **数据：** 约 3 万小时真实场景数据，计划 2026 年底达到 15–20 万小时；自研 MORPHI Sense Kit 采集设备；先在酒店、商务公寓场景采集，再进入家庭。
- **路线名：** **Agentic-Native（智能体原生）**。

### 1.2 核心主张

传统双系统 / 分层 VLA 的常见分工是：

```text
System 2（云端 VLM/LLM，低频）
  ├─ 理解意图
  ├─ 拆解任务
  ├─ 维护目标
  ├─ 管理执行历史
  ├─ 追踪进度
  └─ 失败后重新规划
        ↓ 固定格式文本子任务
System 1（端侧动作策略，高频）
  └─ 接收子任务 → 结合视觉/本体状态 → 输出动作
```

MoRA 的批评是：这种结构里 **Agentic 能力全在 System 2，System 1 只是"大模型外挂的动作策略"**。后果是：

1. **目标接口窄**：System 1 只能接收固定格式文本子指令，不支持图像指令和多阶段结构化目标，层层转译造成信息损耗。
2. **执行短时序、反应式**：System 1 没有进度认知和多粒度记忆，遇到扰动只能停下等 System 2 重规划，表现为"一卡一卡"。

MoRA 的改造方向：**把目标持续性、执行记忆、进度判断下沉到 System 1 内部**，让 System 1 从"输出下一个动作"变成"持续工作"；System 2 退到意图理解、全局规划、异常兜底和人机协同的位置。这就是 **Agentic-Native**。

## 2. MoRA 架构拆解

### 2.1 三层职责（A/B 级信息混合）

> 注意：官方口径主要讲 **System 1 / System 2 两层**。System 0（≥100Hz 全身运控）出现在部分媒体解读和行业对照中（如与 Figure Helix 02 的三层结构对比），**并非所有来源都确认 MoRA 官方定义了 System 0**。本仓库借用三层命名，属于工程映射。

```text
System 2：认知中枢 / "项目经理"（云端，低频，高时延可接受）
  ├─ 意图理解
  ├─ 任务规划与编排
  ├─ 约束与异常兜底
  ├─ 多模态交互（与人协作）
  └─ 向 System 1 下发结构化目标（文本 + 图像）
        ↓
System 1：Agentic 执行引擎 / "主力员工"（端侧，≥10Hz）
  ├─ 目标条件执行（Goal-Conditioned Execution）
  ├─ 多粒度执行记忆（短期 / 中期 / 长期）
  ├─ 进度认知闭环（Progress-Aware Closed Loop）
  ├─ 输出动作块 / 未来预测 / 文本反馈
  └─ 自主纠偏；超出能力边界时才请求 System 2 介入
        ↓
System 0：小脑 / 全身运控（端侧，≥100Hz；媒体/行业口径）
  └─ 把动作块展开为关节/轮组控制指令
```

### 2.2 System 1 的三项核心能力（A 级，官方口径）

#### 能力一：目标为条件的持续执行（Goal-Conditioned Execution）

- 输入不再是"拆好的子任务"或离散动作指令，而是由**文本 + 图像共同定义的结构化任务目标**。
- 目标接口**内化进策略模型**，减少跨层转译。
- 策略始终围绕最终状态，知道"什么状态才算完成"。
- 支持多阶段目标，而不是单步子任务。

#### 能力二：多粒度执行记忆（Multi-Granularity Memory）

| 时间尺度 | 记忆内容 | 作用 |
| --- | --- | --- |
| **短期** | 毫秒级控制连续性 | 保持动作平滑、避免抖动 |
| **中期** | 步骤级执行状态 | 记住"当前做到哪一步、上一步结果如何" |
| **长期** | 整体目标与任务进度 | 跨区域、跨视角保持任务连续性 |

- 记忆以 **Memory Token** 形式进入模型表征空间（B/C 级描述）。
- 官方强调：记忆**不是外部状态机**，而是模型内部表征的一部分。
- 公开资料未披露：记忆的存储结构、更新频率、遗忘机制、容量、是否可微、是否跨回合保留。

#### 能力三：进度认知闭环（Progress-Aware Closed Loop）

```text
目标 + 执行记忆 + 环境反馈
        ↓
   输出动作
        ↓
   自评任务状态 / 当前进度
        ↓
   局部偏差 → System 1 自主修正
   边界/异常 → 请求 System 2 介入
```

- System 1 不只输出动作，还输出**任务状态、当前进度、是否需要 S2 介入**。
- 多数中途偏差由 System 1 自行感知并修正，减少跨层往返。
- 公开资料未披露：进度如何定义/监督、介入阈值、失败检测机制。

### 2.3 System 1 的输入输出（B/C 级，媒体架构图转述）

部分媒体对架构图的转述如下（**未经官方文档确认**，仅作为设计方向参考）：

```text
输入：
  - Structure Text Prompt（结构化文本目标）
  - Vision Prompt（视觉提示 / 目标图像）
  - Memory Token（记忆 token）
  - Noisy Actions（带噪动作 / 动作历史）
  - Tactile Token（触觉 token）

输出：
  - Action Chunk（动作块）
  - Future Prediction（未来预测 / 未来画面或状态）
```

同时，甲子光年提到 System 1 内部包含**理解、世界、动作、触觉四类专家**（B 级），输出端还包括给 System 2 的交互文本、任务状态、进度和介入信号。另一来源则称 System 2 是 "VLM Harness"，包含 Understanding Expert 与 World Expert（C 级）。这些划分在不同报道中不一致，**不应视为确定架构**。

### 2.4 训练信号（B 级）

甲子光年提到：

- 只用动作作为训练信号，信息量不足。
- 输入侧加入视觉、语言、触觉；输出侧加入**未来画面预测、语言反馈**等辅助任务。
- 未来预测提供空间变化信号；语言提供逻辑监督；触觉补充接触反馈。
- 未披露损失函数、权重、参数量、专家路由、融合方式，也未明确是否端到端训练。

### 2.5 数据与工程（A/B 级）

- 数据质量优先于模型架构（黄青虬原话大意）。
- 约 3 万小时真实作业数据；目标 15–20 万小时。
- MORPHI Sense Kit：无本体采集设备，弱纹理/高反光场景下毫米级轨迹重建。
- **统一具身动作空间（Unified Embodied Action Space）** + **具身迁移（Embodiment Transfer）**：先从人类数据抽取与本体无关的任务知识，再映射到机器人。
- 数据闭环：云端质检、场景重建、挖掘、标注 → 训练 → 评测 → 真机回流。
- 单次迭代约一周，目标压缩到一天。

### 2.6 公开资料的空白清单

以下问题**没有公开答案**，任何声称"MoRA 就是这样实现的"都需要警惕：

- 模型参数量、骨干网络、是否端到端。
- 损失函数、辅助任务权重、训练配方。
- 专家数量、路由方式、融合机制。
- Memory Token 的具体形式、更新/遗忘规则、是否跨 episode。
- 进度的定义、监督来源、介入阈值。
- System 1 的确切运行频率（只知 ≥10Hz 的量级说法）。
- System 0 是否属于官方架构。
- 动作块的时长、执行方式、与底层控制的接口。
- 真机成功率、量化评测协议。

### 3.3 关键判断

1. **"MoRA-inspired" 目前只落在层次命名上。** 仓库借用了 S0/S1/S2 的分工，但 MoRA 的真正主张——Agentic 能力内化到 S1——没有实现。
2. **仓库的 "记忆" 是环境状态机，不是策略记忆。** `compute_mora_obs` 里的 `segment_idx`、`passed`、`docking` 都是环境侧已知量。策略没有历史编码，也没有跨步隐藏状态；它只是读取了状态机算好的结果。
3. **仓库的 "目标条件" 是特征拼接，不是目标内化。** 目标以 2–7 个数值追加到观测末尾，策略并没有学习"目标表示"或"完成判定"。
4. **仓库的 "进度" 是奖励塑形，不是认知闭环。** `_progress_metric` 由环境计算，`progress_rate` 直接进观测；策略不输出进度，也没有介入/降级行为。
5. **仓库的 S2 是规则，不是认知中枢。** 这是 README 已明确承认的边界，不应在对外表述中模糊。
6. **仓库的 S0 是脚本教师。** 差速转向、停靠、岔路转向都由已知几何决定；PPO 主要调速度。这与 MoRA 的 S0 运控也不是同一类东西。

## 4. MoRA-inspired v2：升级路线

### 4.1 设计原则

1. **一次只验证一个机制。** 仓库已有实验完整性问题（多变量同时改动导致无法归因），v2 不应重复这个错误。
2. **先做减法，再做加法。** 先把外部手写状态从观测中移除，逼策略使用历史；再加记忆模块。否则"记忆"会被外部状态机掩盖。
3. **每个模块都要有可证伪指标。** 不能只报告任务成功率；要有记忆/进度/介入各自的代理指标。
4. **保持三层边界不变。** S2/S1/S0 的接口先冻结，避免架构与训练同时变化。

### 4.2 目标架构（MoRA-inspired v2）

```text
System 2（规则或轻量规划器，~1Hz）
  └─ 输出 GoalSpec：阶段列表、每阶段目标、停止条件、可选目标图像
        ↓
System 1（学习型策略，10–100Hz）
  ├─ Goal Encoder：GoalSpec → goal tokens
  ├─ Memory Bank：
  │    ├─ 短期：GRU/Transformer hidden state
  │    ├─ 中期：step-level memory tokens
  │    └─ 长期：task progress summary token
  ├─ Backbone：proprio encoder + memory + goal cross-attention
  └─ Heads：
       ├─ Action head（动作或动作块）
       ├─ Progress head（预测进度/剩余量）
       ├─ Completion head（是否完成当前阶段）
       ├─ Intervention head（是否请求 S2/S0 降级）
       └─ World-model head（预测下一步关键状态，辅助监督）
        ↓
System 0（脚本或学习型运控，≥100Hz）
  └─ 执行动作块 / 底层控制
```

### 4.3 工作包与最小实验

#### WP1：内化记忆（优先级最高）

**改动：**

- 新增 `rl/mora/memory.py`：短期 GRU/Transformer + 中期 memory tokens + 长期 summary token。
- 新增自定义 SB3 policy（或 `sb3-contrib` 的 `RecurrentPPO`）替换 MLP。
- **消融 A：** 保留 `compute_mora_obs`（外部状态）→ 复现现状。
- **消融 B：** 移除 `segment_idx / passed / docking` 等外部状态，只给原始 61 维观测 + 目标；策略必须从历史推断阶段。
- **消融 C：** 在 B 的基础上加记忆模块。

**指标：**

- 任务成功率。
- **冻结率**（连续 N 步速度低于阈值）。
- **扰动恢复时间**（施加 40N 推力后回到路径的时间）。
- **OOD 起点成功率**（从非自然中间态、不同速度/航向启动）。
- 记忆消融的样本效率（达到同等成功率所需步数）。

**证伪标准：** 如果 C 相对 B 在 OOD 起点和恢复时间上没有显著改善，则"内化记忆"假设不成立，应检查任务是否根本不需要记忆。

#### WP2：进度认知闭环

**改动：**

- 新增 `ProgressHead`：预测归一化进度（0–1）或剩余弧长。
- 新增 `CompletionHead`：当前阶段完成概率。
- 新增 `InterventionHead`：是否需要降级到脚本 S0 / 请求 S2。
- 辅助损失：进度 MSE + 完成 BCE + 介入 BCE（标签由环境事件生成，注意训练/评估隔离）。
- 推理时：用进度头驱动奖励塑形或早停，用介入头触发脚本兜底。

**指标：**

- 进度预测 MAE / 校准误差。
- 介入率（越接近能力边界越高）。
- 从偏差状态恢复的成功率。
- 任务成功率与平均完成时间。

**证伪标准：** 如果进度头不能降低介入率或恢复时间，则它只是多余的辅助任务。

#### WP3：目标表示与多阶段条件化

**改动：**

- 定义 `GoalSpec` 数据类：阶段 ID、目标位姿/弧长、停止条件、目标 A/B、可选目标图像。
- `GoalEncoder`：MLP 编码数值目标；预留图像编码接口（MuJoCo 渲染俯视图或第一人称相机）。
- 目标 token 与观测 token 做 cross-attention，而不是简单拼接。
- 训练时做目标随机化 / goal relabeling，但明确标注这不是标准 HER。

**指标：**

- 未见目标序列的成功率。
- 多阶段任务中阶段切换正确率。
- 目标表示消融（拼接 vs token vs 图像）的样本效率。

**证伪标准：** 如果 token 化目标相对数值拼接没有改善泛化，则复杂目标编码不是当前瓶颈。

#### WP4：频率分层与动作块

**改动：**

- S1 改为 10Hz，输出长度为 10 的动作块（等效 100Hz 执行）。
- S0 保持 500Hz 物理/100Hz 控制。
- 比较：10Hz 动作块 vs 100Hz 单步动作。

**指标：**

- 动作 jerk / 平滑度。
- 任务成功率。
- 推理延迟与计算量。

**证伪标准：** 如果动作块没有改善平滑度或成功率，则频率分层在该任务上不成立。

#### WP5（可选）：多专家与多模态辅助

- `ProprioEncoder` + `VisionEncoder`（MuJoCo 相机）+ `TactileEncoder`（MuJoCo contact force）。
- `WorldModelHead`：预测下一步关键状态或未来画面低维特征。
- 注意：这会让系统复杂度和数据需求大幅上升，**不建议在 WP1–WP4 之前做**。

### 4.6 与仓库现有完整性原则的衔接

仓库已经建立了很好的证据纪律（见 `docs/INTEGRITY_UPGRADE.md` 与 `docs/EXPERIMENTS.md`）。v2 应延续：

- 不把多变量同时改动的结果归因给单一模块。
- 不把"完整系统成功"表述为"某个机制有效"。
- 不把历史报告的成功率追认为新架构的结果。
- 公开 checkpoint、归一化统计和训练配置，否则复现性仍然不足。
- 明确区分 `MoRA-inspired` 与官方 MoRA。

## 5. 风险与边界

1. **不可比性：** 官方 MoRA 是真实家庭场景、视觉+触觉、3 万小时数据、端侧部署；本仓库是 MuJoCo 特权状态、脚本教师、单一任务集。两者不在同一证据等级。
2. **命名风险：** 继续使用 "MoRA-inspired" 可以，但必须保留 README 中的边界声明；不应在简历/对外材料中暗示复现了 MoRA。
3. **任务规模风险：** 当前任务（弯道、多段、岔路）可能根本不需要多粒度记忆；如果 WP1 证伪，应诚实报告"该任务集不足以检验记忆假设"。
4. **实现风险：** 自定义 recurrent policy + 辅助头的训练稳定性、VecNormalize 与记忆状态的兼容、episode 边界的状态重置，都是工程难点。
5. **数据风险：** 仿真特权状态无法替代视觉/触觉；如果目标是 MoRA 式的能力，最终需要相机与接触传感器，甚至实机数据。
6. **统计风险：** 20/20、40/40 是批次内成功率，不是总体失败率为零；v2 必须用独立种子和置信区间说话。

---

## 6. 推荐下一步

按投入产出比排序：

1. **WP1 的记忆消融（E1/E2）**：这是最能检验 "MoRA-inspired" 是否名副其实的实验，而且不需要视觉/语言/触觉。
2. **WP2 的进度头**：工程量适中，能直接对应 MoRA 的 "Progress-Aware Closed Loop"。
3. **WP3 的目标 token 化**：如果目标是发论文/做作品集，目标表示是更容易讲清楚的技术点。
4. **WP4 的动作块**：工程改动小，适合作为频率分层的补充实验。
5. **WP5 多模态**：成本最高，建议留到有视觉/触觉数据之后。

**一句话建议：** 先把 `compute_mora_obs` 这个"伪记忆"拿掉，让策略真正依赖历史；再逐步加记忆、进度和介入。否则无论加多少模块，都无法证明它们不是被外部状态机替代了。
